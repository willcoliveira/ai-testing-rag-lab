# raglab v0.1.0: the lab core (2026-10-20)

v0.1 closes P1 of the main plan: "A working, tested lab with real local results and a container
ready to deploy." It is **experimental**: the models are fake or local, so the numbers are real but
local, made on one maintainer's Mac. The release followed `runbooks/release.md`, from the plan
`docs/plans/2026-10-20-v0.1-release.md`.

## What it holds (S0 to S4)

- **S0, the skeleton.** `make check` and pr-fast run lint, types, dependency and dead-code checks,
  vulnerability, SAST, workflow and secret scans, the privacy check, architecture rules and the
  offline tests. Commits and branches follow Conventional Commits and semantic names, with
  CHANGELOG lines.
- **S1a and S1b, the corpus and its ingestion.** A fictional two-tenant policy corpus (Halvenroot
  and Mirrowfen) with a planted-feature answer key. Markdown, PDF, HTML and OCR parsers; a
  section-aware chunker; a committed inventory snapshot.
- **S2, retrieval without a judge.** The local bge-small embedder; dense, BM25 and hybrid
  retrievers with a tenant filter that fails closed; hit@k, MRR and recall@k with paired bootstrap
  comparisons; run record v1; `raglab publish`; the recall@5 no-regression gate in pr-fast.
- **S3, generation.** A versioned prompt, input limits, the tenant guard and the citation
  validator. The API, a page and a container (non-root, digest-pinned, ZAP baseline). The local
  model on Ollama, for one guarded session at a time only.
- **S4, the golden set and the consistency gate.**
  - Golden set v1.1: 34 retrieval questions and 40 behaviour cases, signed off by the maintainer.
  - `check-dataset` as a hard stop.
  - The behaviour checks.
  - The consistency gate (behaviour pass^3 on dev, local until keys), with a margin set from five
    runs.

How to start: `docs/ONBOARDING.md`. The local model: `docs/LOCAL-MODEL.md`.

## The test slice

The test split is held out. It ran for this release only, under gate `release`, and is reported,
not gated. No threshold was set from it and nothing was tuned on it.

- The generation test split ran once.
- The retrieval test split ran twice, with the same numbers. A first attempt at `18b7d05` made the
  retrieval run, then stopped before any generation call, because a generation run must use its
  config's split. That run stays unpublished, and the plan's ledger records it.

| recall@5 | 0.792 | 0.625 to 0.958 |

answer-v1. Rates use 95% Wilson intervals at n cases.

| **behaviour pass^3** | **0.308** (4 of 13) | 0.127 to 0.576 | 13 |

- **Every behaviour case-trial was labelled `answer`** (39 of 39). The 8 answer cases had the right
  label in every trial. Four of them (G-07, G-15, G-18, G-35) pass behaviour pass^3; the other four
  (G-02, G-04, G-20, G-32) cited no labelled chunk in any trial, so they fail it. The 3 abstain,
  1 flag-conflict and 1 refuse-and-help cases had the wrong label in every trial.
- **Abstain cases stated a value.** In 7 of their 9 trials the answer stated a value; in 2 it
  stated none. This is S3's abstention finding, measured on dev in S4 and again here; v0.1 ships
  prompt answer-v1 with it, as the maintainer decided (S4's D1).
- **For context, not a comparison:** on dev, behaviour pass^3 is 0.519 (14 of 27, 0.340 to
  0.693). The test split has 13 cases with a different mix, and the intervals overlap.
- **Run facts:** 75 of 75 case-trials ok; latency p50 1458 ms and p95 2813 ms. The session
  (contract test and suite) and the retrieval run took 2 min 53 s together. The postcheck
  passed: port closed, no ollama process, no model loaded.

## Known limits

- **Local only.** One Mac, one local model; no hosted provider until keys exist (ADR-002).
- **Quality isn't judged yet.** "Cites a labelled chunk" is not correctness; S5 adds the judge.
- **Abstention.** The model rarely gives any label but `answer`, as above. A prompt change
  (answer-v2) is a follow-up, measured against S4's baseline.
- **Small and synthetic.** One author, 40 behaviour cases, so the intervals are wide.
- **Not reproducible to the word.** The same seed does not reproduce the text on Ollama 0.40.6's
  MLX runner; pass^3 held steady because it reads labels and citations, not wording (S4 ledger).
- **The container is ready to deploy, not deployed.** Its ZAP baseline ran on the Mac.
